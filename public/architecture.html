How it works Architecture GitHub

Architecture

Three layers. A weekly build turns FDA label files into a search index and lookup tables. Two small Python functions answer requests. A static page talks to them.

The weekly build

Every Monday, and on every change to the code, a GitHub Actions job rebuilds everything from scratch and deploys. openFDA publishes its label data weekly; this runs the day after.

  1. 1DownloadThe openFDA drug-label bulk files. 262,883 label records.
  2. 2CollectKeep human prescription labels with named ingredients; keep the newest label per ingredient set. 2,481 labels.
  3. 3Map ingredientsEach substance is rolled up to its base ingredient through RxNorm, so a salt and its parent count as the same drug.
  4. 4TagEvery label is tagged with the 17 vocabulary terms below by fixed rules over named label fields. Each tag keeps the sentence that earned it.
  5. 5IndexA BM25 search index over each label's main text, plus the checker's per-label tables.
  6. 6Test and deploy322 Python tests and 109 front-end tests must pass. Then the built files go to Vercel.

At request time

  1. 1BrowserSends the list to /api/check.
  2. 2ResolveLocal dictionary first; RxNorm for typos.
  3. 3RulesShared risks, named contraindications, duplicates.
  4. 4ReplyAlerts with sentence, section, and DailyMed link.

A word that isn't a medication goes to /api/search instead, which ranks label text with BM25 and returns the matching sentence from each label.

The vocabulary

Seventeen terms, each assigned by one fixed rule over named openFDA fields, so the same label always gets the same tags. The four interaction-risk terms drive the checker.

Nothing outside this list is used. The full record, with access dates and licenses, is in DATA_SOURCES.md.

How it is kept honest

  • Every function, in Python and TypeScript, has a three-line comment saying what it takes, does, and gives. A test fails the build if one is missing.
  • A tag with no evidence sentence is never assigned; an alert with no evidence is never raised.
  • A harness runs 41 blind-test medication lists through the live API and publishes the score, misses included: validation report.
