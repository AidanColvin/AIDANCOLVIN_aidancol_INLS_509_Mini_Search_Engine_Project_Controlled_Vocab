How it works Architecture GitHub

Architecture

Three layers. A weekly build turns FDA label files into a search index and lookup tables. Two stateless Python functions answer requests. A static page talks to them.

Sources

Four external sources. Each feeds one part of the system, and nothing else is used.

NLM RxNorm (RxNav)Base-ingredient rollup for every substance at build time. Approximate name matching at request time, for names the local dictionary cannot place.Build and request

The weekly build

Every Monday, and on every change to the code, a GitHub Actions job rebuilds everything from the bulk files and deploys. openFDA updates weekly; this runs the day after.

  1. 1DownloadThe openFDA drug-label bulk files. 262,883 label records.
  2. 2CollectKeep human prescription labels that carry openFDA metadata and a substance name. Keep only the newest label per ingredient set. 2,481 labels remain.
  3. 3Map ingredientsEach substance is rolled up to its base ingredient through RxNorm, so "sertraline hydrochloride" and "sertraline" are one drug.
  4. 4TagEvery label is tagged with the 17 vocabulary terms by fixed rules over named fields. Each tag keeps the sentence that earned it.
  5. 5IndexA BM25 index over each label's text, plus the name dictionary and the checker's per-label tables.
  6. 6Test and deploy322 Python tests and 106 front-end tests must pass. Then the built files go to Vercel.

Tagging

Each of the 17 terms has one rule: a list of label fields to read, in order, and a pattern to find. The first sentence that matches becomes the term's evidence. A term with no evidence is never assigned. The same label always gets the same tags.

Ranking

Search is BM25 over one document per label. A document is the label's indexed text fields joined with its openFDA brand, generic, and substance names. Tokens are lowercased runs of letters and digits. There is no stemming and no stop-word list, so "spasm" and "spasms" are different terms. The average document is 3,872 tokens.

  1. 1FilterSelected vocabulary terms narrow the set first: every term (AND) or any term (OR).
  2. 2RankThe remaining labels are scored with BM25 and sorted, best first.
  3. 3Snippet80 characters either side of the first query word in the label's text.
score(D, Q) = Σt ∈ Q  IDF(t) · tf(t, D) · (k₁ + 1) / ( tf(t, D) + k₁ · (1 − b + b · |D| / avgdl) )

IDF(t) = ln( (N − n(t) + 0.5) / (n(t) + 0.5) + 1 )

k₁ = 1.2    b = 0.75    N = 2,481    avgdl = 3,872
SymbolMeaning
tf(t, D)How many times term t occurs in label D.
n(t)How many labels contain t. Rare terms score higher.
|D| / avgdlThis label's length against the average. Long labels are penalized so they don't win on bulk.
k₁How quickly repeated occurrences stop adding score.
bHow much length matters, from 0 (not at all) to 1 (fully).

Name resolution

A typed entry is parsed into a name, a strength, and a frequency. The name is then matched in stages. The first stage that succeeds wins.

  1. 1Exact matchAgainst the local dictionary of every brand, generic, and ingredient name in the collection.
  2. 2Close matchSequence similarity against the dictionary, whole name and leading words. Accepted at 0.85 or better. "trazdone" matches "trazodone".
  3. 3RxNorm approximate matchRxNav's approximateTerm, then the concept's ingredients, then the collection label for that ingredient set. An exact RxNorm name beats a weaker local guess.
  4. 4Ask, don't guessIf two products fit equally, the entry is marked "needs confirmation" and the choices are shown. Salt forms of one molecule are settled automatically.

The checker

One request runs three rules over the resolved labels. Each rule reads only the tags and sentences produced at build time.

Group Two or more listed drugs carry the same interaction-risk tag: Serotonin Syndrome, CNS Depression, or QT Prolongation. One alert per shared tag, with every member's own sentence.
Pair Drug A's Contraindicated Combination sentence names drug B, or B's pharmacologic class, as whole words. Hypersensitivity and self-reference clauses are ignored.
Duplication Two entries share a base ingredient, or one is the other's active metabolite in a small reference list. Their daily totals are summed.

An alert's tier is the label section its sentence came from: contraindications, boxed warning, warnings and precautions, or drug interactions. The section is a heuristic for seriousness, and every alert says so.

  1. 1ParseSplit entries; read name, strength, frequency.
  2. 2ResolveDictionary, then RxNorm.
  3. 3RulesGroup, pair, duplication.
  4. 4ReplyAlerts with sentence, section, tier, DailyMed link.

How it is kept honest

  • A tag with no evidence sentence is never assigned. An alert with no evidence is never raised. Nothing is paraphrased.
  • Every function, in Python and TypeScript, has a three-line comment saying what it takes, does, and gives. A test fails the build if one is missing.
  • A harness runs 41 blind-test medication lists through the live API and publishes the score, misses included: validation report.
